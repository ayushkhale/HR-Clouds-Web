# Background Jobs & Queues

## Overview
HRMS offloads heavy calculations, timed operations, and report generation to background workers to ensure the main API remains highly responsive.

## Key Workers

### 1. Attendance Calculation Engine
- **Trigger**: Called directly via `calculationService` during Clock Out or Regularization Approvals, but historically/architecturally intended to be swept via a nightly cron.
- **Purpose**: Recalculates effective hours, lateness, and overtime for all `in_progress` records.

### 2. Anomaly Detection
- **Trigger**: Real-time upon specific actions (e.g., Clock In without coordinates), but can also be run as a nightly sweep to catch "Missing Clock Out" anomalies.

### 3. Biometric Webhook Processor
- **Trigger**: The `/devices/webhook` API.
- **Purpose**: The API itself is synchronous but extremely lightweight (only writes to `attendance_logs`). A decoupled background worker (conceptual) sweeps `attendance_logs` where `source=biometric` to update `attendance_records` and `attendance_sessions`. This prevents device timeouts if the database is under load.

## Cron Jobs (Scheduled Tasks)
*Note: Depending on the deployment environment, these are usually triggered via OS crontab or a Node-based scheduler (e.g., node-cron) hitting internal endpoints.*

- **Nightly Status Finalization (Midnight)**: Closes out open sessions that forgot to clock out, marking the record as `absent` or `half_day` depending on the effective hours, and generating an anomaly.
- **Monthly Leave Accrual (1st of Month)**: Credits employee leave balances based on their assigned leave policies.
- **PDF Render Worker (`*/15 * * * *` IST)** — `src/cron-jobs/pdf_render_worker.cron.js` (PDF Generation Phase 3; extended in Phase 4): first drains a bounded batch of every `html`-engine org's payslip render queue (`payroll_automation.runPayslipRender` — a `pdfkit`-engine org is skipped, so that half is a no-op until an org opts in). Then, in its **own** `try/catch`, drains every org's **letter** render queue (`document_automation.runLetterRender`) — this half is **not** gated on any engine setting (letters are always HTML) and is the unattended drain for bulk-letter batches (#143) and any queued single issue. The two drains are independent: a letter-side failure never stops the payslip drain or vice versa. ≥15-minute interval per the compute-hour preservation rule. Never rethrows.
- **PDF Artifact Sweeper + EC-19 Verification (04:00 IST)** — `src/cron-jobs/pdf_artifact_sweeper.cron.js` (extended in Phase 3): after the stale-pending sweep it runs `document_automation.runArtifactVerification` — a report-only `HeadObject` pass over `ready` **record**-class artifacts (letters) that logs `pdf.record.object_missing` for a lost object and never mutates a row.
- **PDF Cache Purge (04:15 IST)** — `src/cron-jobs/pdf_cache_purge.cron.js` (PDF Generation Phase 3): purges `cache`-class artifacts older than each org's `pdf_cache_retention_days` (object first, then row; `record`-class is unreachable) and reaps terminal render jobs older than 90 days. Scheduled ≥15 minutes after the 04:00 sweeper so the two destructive jobs never contend. Never rethrows.
- **Document Offboarding Archiver + Letter Auto-Issue (02:30 IST)** — `src/cron-jobs/document_offboarding_archiver.cron.js` (Documents Phase 5; extended in PDF Generation Phase 4): first runs `document_automation.runOffboardingArchive` (archives/retains a leaver's documents per `document_offboarding_archive_mode`, waiving open acknowledgements and cancelling open requests). **Then, in the same `try` and strictly after the archive**, runs `document_automation.runLetterAutoIssue` — which issues each template listed in each org's `letter_auto_issue_on_exit` (#92) to employees whose last working day has arrived, idempotently under `keyBase autoexit:{exitId}:{code}`. **The ordering is a correctness property, not an optimisation:** the archive waives the leaver's acknowledgement/notification obligations, so a letter auto-issued *before* the archive would be silently un-acknowledgeable and unmailed. An exit with no attributable actor (`recorded_by` null) is skipped, not guessed. Empty `letter_auto_issue_on_exit` ⇒ the pass reads nothing beyond settings and returns. Scheduled 15 minutes after `payroll_auto_draft` (02:15) and well after the 00:30 expiry flip. Never rethrows.
- **Document Sweeper (03:45 IST)** — `src/cron-jobs/document_sweeper.cron.js` (Documents Phase 4; extended in PDF Generation Phase 5): `document_automation.runSweeper({})` runs five passes per org, in order:
  1. **Abandoned uploads** (existing) — removes `pending_upload` rows older than 24 h, object-before-row.
  2. **Employee-document retention** (existing) — hard-deletes soft-deleted uploaded documents past retention; statutory types are never swept.
  3. **Letter retention (NEW — PDF Generation Phase 5, F-3)** — `_sweepLetterRetention` hard-deletes soft-deleted **generated** letters (`origin='generated'`) past their effective retention (`letter_record_retention_days` #95 ?? `document_retention_days`, then the type's own retention if longer). A letter is skipped, at any age, if it has an open acknowledgement obligation (BR-2), a statutory type (BR-3), or a live successor version (`supersedes_id` points at it, BR-5 — version chains drain newest-first across successive nights). Deletion order per candidate: S3 object first (a failed `deleteObject` keeps the row for the next run; a `StorageUnavailableError` aborts this org's pass and others continue), then one transaction that clears the RESTRICT children (signature requests → acknowledgements → recipients), hard-deletes the row, tombstones its render artifact (`status='purged'`, `storage_key=NULL`), and writes a `letter.purged` audit row carrying no storage key. **This is the only irreversible thing the sweeper does.**
  4. **Branding-asset quarantine (NEW — PDF Generation Phase 5, F-4)** — `_sweepBrandingAssets` drains each org's `document_letter_branding.superseded_asset_keys`, deleting objects quarantined for ≥ 1 hour (BR-10). Objects are deleted outside the advisory lock; the column is then rewritten under the branding row's existing advisory lock so a concurrent `confirmAsset` append is never lost. A failed delete keeps the key for the next run.
  5. **Outbox purge** (existing) — purges sent/skipped notification outbox rows older than 90 days.
  - **Ordering is a correctness property, not an optimisation:** Pass 3 runs at 03:45, strictly *before* the 04:00 `pdf_artifact_sweeper` EC-19 verifier. A letter purged tonight is already a `purged` tombstone (not `status='ready'`) when the verifier's `HeadObject` pass looks, so it is excluded and never re-alarms as an object-missing (§13.5). The ≥15-minute spacing between destructive jobs is preserved throughout.
  - **Dry run:** `runSweeper({ dryRun: true })` runs every selection, guard and count but performs zero deletes and opens zero transactions ("changes nothing"). One dry run per environment is required before the letter purge is trusted — see the runbooks below. The only destructive job of the night, so it is never part of startup catch-up. Never rethrows.
