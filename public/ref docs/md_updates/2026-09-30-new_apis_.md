# New APIs - September 30, 2026

Three newly shipped APIs in the Organization module: two read-only org views and a production-grade
profile-avatar upload. All are additive — no existing route, request or response changed.

> **Authoritative registry:** the encoded machine registry lives at `public/md_system/api_registry.md`.
> This file is the human-readable running list for the frontend, matching the `new_apis_*` convention.

## Group A — Organization Module (Read)

### 1. Get Organization Details (New)
* **Endpoint:** `GET /api/v1/organizations/details`
* **Allowed Roles:** `hr`, `manager`, `employee`
* **Description:** Company detail sheet — org core row + `organization_profiles` + HR contacts + light stats (active member counts by role, department/location counts).
* **Payload / Query / Path Params:** None.
* **Notes:** `profile.gst_number` and `profile.company_pan_number` are returned **only to `hr`** (keys are absent, not null, for other roles). `profile` may be `null`. HR-contact avatars are resolved to presigned URLs. Full contract: `public/md_organization/6_org_details_and_hierarchy_api.md`.

### 2. Get Organization Hierarchy (New)
* **Endpoint:** `GET /api/v1/organizations/hierarchy`
* **Allowed Roles:** `hr`, `manager`, `employee`
* **Description:** Live org chart of all **active** members wired from the `user_reporting_mappings` backbone. `data = { total_members, roots[] }`; each node has `children[]` recursively and exposes `reporting_to_id`.
* **Payload / Query / Path Params:** None.
* **Notes:** Whole-org view (same visibility class as `/directory`); node fields are public-safe (no PAN/UAN, addresses, DOB, personal email). Node avatars are resolved to presigned URLs. No pagination — virtualize client-side. Full contract: `public/md_organization/6_org_details_and_hierarchy_api.md`.

### 3. Profile Avatar Upload (New) — presigned two-step handshake
* **Endpoints:**
  * `POST /api/v1/organizations/me/avatar/upload-url` — step 1, mint a presigned PUT + signed claim token.
  * `POST /api/v1/organizations/me/avatar/confirm` — step 3, verify + persist, returns the updated profile.
* **Allowed Roles:** `hr`, `manager`, `employee` (self only).
* **Description:** Lets any tenant member set/replace their own avatar. The browser PUTs the image bytes straight to the private bucket; the API never proxies the file. The avatar is served as a short-lived (~5 min) presigned URL on every org-module read.
* **Payload:**
  ```json
  // step 1
  { "content_type": "image/png", "size_bytes": 84213, "file_name": "me.png" }
  // step 3
  { "storage_key_token": "<opaque token from step 1>" }
  ```
* **Notes:** Types PNG/JPEG/WebP, ≤ 5 MB. Confirm re-verifies the real content type/size from the object's HEAD (not the client's claim). Idempotent on replay. Requires DB migration `00061-add-avatar-storage-key-to-user-profiles`. Errors: 413/415/429 (step 1), 404 `UPLOAD_CLAIM_NOT_FOUND` / 409 `UPLOAD_NOT_FOUND` (step 3), 503 `STORAGE_UNAVAILABLE`. **Cross-module limitation:** attendance/leave/payroll views won't show uploaded avatars until they adopt the resolver (external OAuth URLs still render everywhere). Full contract: `public/md_organization/7_avatar_upload_api.md`.
