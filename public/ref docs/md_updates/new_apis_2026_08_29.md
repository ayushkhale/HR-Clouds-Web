# New APIs - August 29, 2026

This document outlines the 8 newly shipped APIs for frontend integration, aligned with the API Registry.

## Group A — Attendance (Self-Service)

### 1. Cancel Regularization Request
* **Endpoint:** `POST /api/v1/attendance/regularizations/:id/cancel`
* **Description:** Withdraws a pending regularization request.
* **Payload:** None.
* **Path Params:** `id` (UUID of the regularization request).
* **Notes:** Enforces a transaction with `LOCK.UPDATE` row lock, self-ownership check (403 if `request.user_id !== userId`), and status re-check (rejects already-processed) to close the lost-update window. Status field is updated to `cancelled` (STRING(20)). No migration needed.

### 2. Get My Overtime
* **Endpoint:** `GET /api/v1/attendance/overtime/mine`
* **Description:** Fetches paginated overtime requests for the logged-in user.
* **Payload:** None.
* **Query Params:** `page`, `limit` (max 100).
* **Notes:** Reuses existing `overtimeService.getEmployeeOvertime`.

### 3. Get My Anomalies
* **Endpoint:** `GET /api/v1/attendance/anomalies/mine`
* **Description:** Fetches paginated attendance anomalies for the logged-in user.
* **Payload:** None.
* **Query Params:** `status` (Enum: `open`, `resolved`, `all`), `page`, `limit`.
* **Notes:** Powered by new `anomalyService.getMyAnomalies` + `findByUserPaginated`.

## Group B — Leave (Self-Service)

### 4. Get My Leave Types
* **Endpoint:** `GET /api/v1/leaves/my-leave-types`
* **Description:** Retrieves active leave types tailored to the caller's per-user config.
* **Payload:** None.
* **Notes:** Handled by new `leaveBalanceService.getMyLeaveTypes`. Designed to populate frontend leave dropdowns.

### 5. Get Single Leave Request
* **Endpoint:** `GET /api/v1/leaves/requests/:id`
* **Description:** Fetches details of a specific leave request belonging to the user.
* **Payload:** None.
* **Path Params:** `id` (UUID of the request).
* **Notes:** Ownership enforced in the query predicate (`user_id` + `org_id`), yields a 404 on miss (protects against IDOR).

## Group C — Organization / Profile (Self-Service)

### 6. Get My Profile
* **Endpoint:** `GET /api/v1/organizations/me`
* **Description:** Fetches the logged-in user's full profile.
* **Payload:** None.
* **Notes:** Reuses `getEmployeeById(req.user, req.user.id)`.

### 7. Update My Profile
* **Endpoint:** `PATCH /api/v1/organizations/me`
* **Description:** Updates the user's personal profile fields.
* **Payload:**
  ```json
  {
    "name": "Jane Doe",
    "phone_number": "+1234567890",
    "avatar_url": "https://example.com/avatar.jpg"
  }
  ```
* **Notes:** Powered by `updateMyProfile`. Enforces a strict whitelist (`unknown(false)` configuration) and forcefully rejects attempts to edit `department`, `designation`, `gender`, `marital_status`, `employee_code`, or `pan_number`. Updates both `users` and profile tables in one atomic transaction, always scoped to `actorUser.id` (no IDOR).

### 8. Get Employee Directory
* **Endpoint:** `GET /api/v1/organizations/directory`
* **Description:** Retrieves public-safe directory data for all employees in the organization.
* **Payload:** None.
* **Notes:** Dedicated directory purpose. Returns only public-safe fields: `name`, `email`, `avatar`, `role`, `department`, `designation`, and `work_location`. Deliberately omits sensitive fields such as addresses, PAN/UAN, DOB, personal email, and marital status.
