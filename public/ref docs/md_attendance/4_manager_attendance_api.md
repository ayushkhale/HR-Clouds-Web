## 1. Get Team Today / Live Status

### Purpose
Fetches the current day's live attendance status for all employees reporting to the authenticated manager. Used for the manager's live team dashboard.

### Endpoint
```
GET /api/v1/attendance/manager/team/today
```

### Authentication and Authorization
- **Authentication:** Required. Bearer token.
- **Role:** `manager`, `hr`, `admin`, `super-admin`.
- **Feature Flag:** `attendance.access` must be enabled.

### Internal Working
1. **Hierarchy Resolution:** Calls `accessControl.getAccessibleUserIds()` which queries `user_reporting_mappings` to recursively find all active subordinates who ultimately report to this manager.
2. If no subordinates, returns empty array.
3. Fetches today's `attendance_records` for the resolved list of user IDs.
4. Returns the records grouped or arrayed, allowing the frontend to calculate "Present", "Absent", "On Break".

### Response Structure
**200 OK**
```json
{
  "success": true,
  "message": "Team today fetched",
  "data": [
    {
      "user_id": "uuid-v4",
      "name": "Jane Smith",
      "status": "in_progress",
      "clock_in_time": "2026-08-21T09:00:00.000Z",
      "active_break": null,
      "shift": { "name": "General", "start_time": "09:00", "end_time": "18:00" }
    }
  ]
}
```

## 3. Get Team Anomalies

### Purpose
Fetches unresolved attendance anomalies (e.g., missing coordinates, out of bounds, excessive breaks) generated by the system for the manager's subordinates.

### Endpoint
```
GET /api/v1/attendance/manager/team/anomalies
```

### Authentication and Authorization
- **Role:** `manager`, `hr`, `admin`, `super-admin`.

### Internal Working
1. Resolves subordinate user IDs via hierarchy check.
2. Queries `attendance_anomalies` where `status === 'unresolved'` and `user_id IN (subordinateIds)`.

### Response Structure
**200 OK**
```json
{
  "success": true,
  "data": [
    {
      "id": "anomaly-uuid",
      "user_id": "uuid-v4",
      "date": "2026-08-21",
      "type": "out_of_bounds",
      "description": "Clock-in occurred outside of assigned location radiuses",
      "severity": "high",
      "status": "unresolved"
    }
  ]
}
```

## 4. Resolve Anomaly

### Business Purpose
Allows a manager to manually resolve/dismiss a system-generated anomaly for a subordinate (e.g. employee forgot their badge but the manager manually verified they arrived on time).

### Endpoint Contract
- **Method:** `POST`
- **Full Endpoint:** `/api/v1/attendance/manager/anomalies/:id/resolve`
- **Authentication:** Required. Bearer token.
- **Authorization:** `manager`, `hr`, `admin`, `super-admin`.

**Path Parameter:** `id` (UUIDv4) of the anomaly.
**Body:**
```json
{
  "remarks": "Discussed with employee, GPS was glitching."
}
```

### Complete Internal Execution Flow
```text
POST /api/v1/attendance/manager/anomalies/:id/resolve
        ↓
AuthMiddleware.authenticate()
        ↓
AttendanceController.handleResolveAnomaly()
        ↓
AnomalyService.resolveAnomaly()
        ↓
AttendanceAnomaly.findOne()
        ↓
AccessControl.getAccessibleUserIds(req.user.id)
        ↓
Verify Anomaly.user_id IN accessible_users (Throws 403 if false)
        ↓
AttendanceAnomaly.update(status: 'resolved', remarks, resolved_by)
        ↓
HTTP 200 OK
```

### Response Structure
**200 OK**
```json
{
  "success": true,
  "message": "Anomaly resolved successfully"
}
```

## 6. Approve / Reject Regularization

### Business Purpose
Allows a manager to formally approve or reject an employee's request to retroactively modify their attendance records. Approval recalculates payroll hours.

### Endpoint Contract
- **Method:** `POST`
- **Full Endpoints:** 
  - `/api/v1/attendance/manager/regularizations/:id/approve`
  - `/api/v1/attendance/manager/regularizations/:id/reject`
- **Authentication:** Required.
- **Authorization:** `manager`, `hr`, `admin`, `super-admin`.

**Body:**
```json
{
  "remarks": "Approved as per discussion"
}
```

### Complete Internal Execution Flow (Approve Flow)
```text
POST /api/v1/attendance/manager/regularizations/:id/approve
        ↓
AuthMiddleware.authenticate()
        ↓
RegularizationController.handleApproveRegularization()
        ↓
RegularizationService.approveRequest()
        ↓
AttendanceRegularizationRequest.findOne(status: pending)
        ↓
AccessControl.getAccessibleUserIds()
        ↓
Verify User Hierarchy (Throws 403 HIERARCHY_VIOLATION if false)
        ↓
LockService.checkLock(request.date) (Throws 403 DATE_LOCKED)
        ↓
BEGIN TRANSACTION
        ↓
AttendanceRegularizationRequest.update(status: approved)
        ↓
AttendanceRecord.upsert(clock_in, clock_out, is_regularized: true)
        ↓
CalculationService.calculateRecord(recordId)
        ↓
Update record with effective_hours, overtime, final status
        ↓
NotificationService.notifyEmployee() (Side effect)
        ↓
COMMIT TRANSACTION
        ↓
HTTP 200 OK
```
