# New APIs - August 31, 2026

This document outlines the 6 newly shipped and updated APIs for frontend integration, specifically focusing on the Organization and Leave modules.

## Group A — Organization / Team Module

### 1. Get Employees List (Updated)
* **Endpoint:** `GET /api/v1/organizations/employees`
* **Description:** Fetches a list of employees. The behavior is now hierarchy-scoped server-side for managers. Managers get only their direct reports with a roster-safe projection, regardless of the `purpose` param they send. HR/admin behavior remains unchanged.
* **Payload:** None.
* **Query Params:** `purpose`, `search` (Optional), `department_id` (Optional), `include_inactive` (Optional).
* **Notes:** Roster-safe projection strips sensitive fields (PAN, UAN, addresses, DOB, personal email, marital status) for managers.

### 2. Get Employee Details (Updated)
* **Endpoint:** `GET /api/v1/organizations/employees/:id`
* **Description:** Fetches details of a specific employee. 
* **Payload:** None.
* **Path Params:** `id` (UUID of the employee).
* **Notes:** IDOR/BOLA vulnerabilities closed. A strict scope check runs before the existence lookup, so an out-of-scope ID and a non-existent ID both return a uniform 403 for managers to prevent enumeration. Self and global approvers are always allowed.

### 3. Update Employee Profile (New)
* **Endpoint:** `PATCH /api/v1/organizations/employees/:id`
* **Description:** Allows managers to edit a direct report's whitelisted personal fields.
* **Payload:** 
  ```json
  {
    "name": "Updated Name",
    "phone_number": "+1234567890",
    "avatar_url": "https://example.com/avatar.jpg"
  }
  ```
* **Path Params:** `id` (UUID of the direct report).
* **Notes:** Cross-team ID returns 403. Self-edit returns 400 (must use `/me`). Role, department, designation, employee_code, and leave-gate demographics are not editable here. Writes to `user_profiles` and role profile atomically via a shared `_writeProfileFields` helper.

## Group B — Leave Module (Team)

### 4. Get Team Leave Requests
* **Endpoint:** `GET /api/v1/leaves/team/requests`
* **Description:** Fetches team leave history (any status).
* **Payload:** None.
* **Query Params:** `status`, `user_id`, page, limit.
* **Notes:** Scoped to direct reports for managers, or org-wide for HR. Includes bounded pagination. The manager's `user_id` filter is validated against scope (BOLA guard).

### 5. Get Team Member Leave Requests
* **Endpoint:** `GET /api/v1/leaves/team/member/:userId/requests`
* **Description:** Fetches a specific direct report's leave history.
* **Payload:** None.
* **Path Params:** `userId` (UUID of the report).
* **Notes:** Fully scoped for managers to ensure they can only query their direct reports.

### 6. Get Team Member Leave Balances
* **Endpoint:** `GET /api/v1/leaves/team/member/:userId/balances`
* **Description:** Fetches a specific direct report's leave wallet at approval time.
* **Payload:** None.
* **Path Params:** `userId` (UUID of the report).
* **Notes:** Fully scoped. Reuses `leaveBalanceService`.
